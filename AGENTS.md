# AGENTS.md

Tauri v2 desktop + Android proxy client (codename Megathrone). Frontend: Vite 7 + SolidJS + Tailwind CSS 4 + DaisyUI 5. Backend: Rust with sing-box bundled as a sidecar binary. Package manager: **pnpm**.

## Commands

```bash
pnpm tauri dev                    # run the app (dev)
pnpm tauri build                  # release bundle
pnpm tauri android build --apk --target aarch64 --ci   # release APK (arm64)
pnpm dev / pnpm build             # frontend only (vite)
pnpm typecheck                    # tsc for BOTH tsconfig.json (src) and tsconfig.node.json (vite.config.ts)
cargo test --manifest-path src-tauri/Cargo.toml --lib      # all Rust tests
cargo test --manifest-path src-tauri/Cargo.toml --lib parser::tests::parses_vmess_base64  # single test
cargo clippy --manifest-path src-tauri/Cargo.toml          # must be warning-free
```

Opt-in parser test against a real subscription file (skipped without the env var):

```bash
MEGATHRONE_REAL_SUB=path/to/sub.txt cargo test --manifest-path src-tauri/Cargo.toml --lib real_world_file
```

Verify a full change: `pnpm typecheck && pnpm build` plus `cargo clippy` and `cargo test --lib`. For android-affecting Rust changes also `cargo check --lib --target aarch64-linux-android` (needs the NDK env below for first-time byedpi/`ring` builds; afterwards the cache suffices).

## Android (local env)

Requires JDK 17+, the Android SDK (platform-tools, platforms;android-36, build-tools;36.0.0) and NDK 29.0.13846066, with `JAVA_HOME`, `ANDROID_HOME`, `NDK_HOME` exported. For a bare `cargo check --target aarch64-linux-android` (no CLI wrapper) also put `$NDK_HOME/toolchains/llvm/prebuilt/*/bin` on PATH and set `CC_aarch64_linux_android`/`AR_aarch64_linux_android` — the real `pnpm tauri android ...` sets its own toolchain. The gradle project in `src-tauri/gen/android/` is committed and meant to be customized (the CLI never overwrites existing files).

## sing-box & byedpi sidecars (build.rs)

- `src-tauri/build.rs` downloads the sing-box binary for the cargo `TARGET` triple before every build (curl + tar, sha256 verified against the GitHub release API digest). No Node scripts involved — do not reintroduce one.
- It also fetches byedpi (`ciadpi`): prebuilt assets for linux/windows, **compiled from the source tarball on macOS** (sha256 pinned in `BYEDPI_SOURCE_SHA256`; upstream publishes no darwin builds) and **compiled from source for android with the NDK clang** (`ndk_clang`, target-prefixed wrapper, min API 24 — upstream publishes no bionic builds). `BYEDPI_VERSION=<x.y.z>` env overrides the pinned version.
- Binaries land in `src-tauri/binaries/` (gitignored) and are cached by `.version` stamp files; reruns are instant. `SING_BOX_VERSION=<x.y.z>` env overrides the pinned version.
- Requires network on first build per target. Direct `cargo build`/`check` works from any entry point (rust-analyzer, VSCode F5) because of build.rs — `beforeDevCommand`/`beforeBuildCommand` are plain `pnpm dev`/`pnpm build`.
- Release-profile darwin builds additionally fetch the other arch's slices and `lipo` them into `<name>-universal-apple-darwin` fat binaries — the bundler requires those (under exactly that name) for `tauri build --target universal-apple-darwin`; the byedpi source compile pins `cc -arch` so the x86_64 slice is a real cross-compile. The GitHub-API digest lookups send `Authorization: Bearer $GITHUB_TOKEN`/`$GH_TOKEN` when set (`.github/workflows/release.yml` passes the workflow token to dodge the 60 req/h anonymous limit).
- Prebuilt byedpi archives name the binary with an arch suffix (`ciadpi-x86_64`) — the extraction search (`find_byedpi_binary`) accepts both it and the bare `ciadpi` the source build produces. `make_executable` is `#[cfg(unix)]`-gated (Windows gets a no-op) — build.rs must compile on every target.
- The release workflow ad-hoc signs macOS bundles (`APPLE_SIGNING_IDENTITY=-`): an unsigned arm64 slice refuses to launch on Apple Silicon, and the job's `codesign --verify` step requires a signature.
- Known limitation: cross-compiling to windows-msvc from macOS fails in `tauri-winres` (missing `llvm-rc`), to linux-gnu in gtk `pkg-config` — upstream Tauri toolchain issues, not this repo's bugs.
- Desktop sidecars ship via `externalBin` — declared in the per-platform overlays `tauri.{macos,linux,windows}.conf.json` (NOT the main tauri.conf.json) so android builds never see it: the CLI ignores `externalBin` on mobile entirely.

## Android sidecars & the process module

- Android apps cannot exec files from their data dir (targetSdk 29+ W^X) and the Tauri CLI does not bundle `externalBin` into an APK. Instead build.rs stages both binaries into `gen/android/app/src/main/jniLibs/<abi>/` as **fake `lib*.so`** (`libsingbox.so`, `libciadpi.so` — the only naming Android's installer extracts into the APK's `nativeLibraryDir` with the exec bit; `useLegacyPackaging = true` in the gradle packaging block forces the extraction). Gradle's `rust` plugin merges that directory into every ABI flavor — no gradle-side changes needed when the binaries change.
- `src-tauri/src/process.rs` is the app's own spawn layer (a faithful subset of the old `tauri-plugin-shell` sidecar API — that plugin is desktop-only and is gone from the project): `process::sidecar("sing-box"|"byedpi")` resolves the binary (exe dir on desktop, `nativeLibraryDir` over JNI via `ndk-context` on Android — initialized by tao, cached in a `OnceLock`), `spawn()` is synchronous and returns the line-based event channel (`CommandEvent::{Stdout,Stderr,Terminated,Error}` — `Terminated` is only delivered after both pipes hit EOF) plus a `CommandChild` (`pid()`/`kill()` over `shared_child`), `output()` awaits completion. All spawns go through it; capabilities never grant any JS process access.
- `src-tauri/src/mobile.rs` is the Android bridge: `set_foreground_service(running)` (no-op on desktop) is called from `connection_connect`/`teardown`; the Kotlin side is `ProxyService` (a `dataSync` foreground service keeping the process — and with it sing-box/byedpi — alive in background) + `ProxyServicePlugin` (registered at setup via `register_android_plugin`, driven by `run_mobile_plugin("setRunning")`).
- The tray (`mod tray`, the `tray-icon` cargo feature, the close-to-tray window handler) is `#[cfg(desktop)]`; `RunEvent::Reopen` stays macOS-only. `lib.rs run()` carries `#[cfg_attr(mobile, tauri::mobile_entry_point)]` — required by the generated mobile shells.
- TUN mode is refused on Android (needs a VpnService-based tunnel, a future project); the mobile UI hides the TUN segment (`ModeControls`, compile-time `BUILD_UI_VARIANT`) and degrades a stored `tun` selection to `system-proxy`. System-proxy wiring stays macOS-only (no-op stubs elsewhere).
- The release APK is signed with the **committed** keystore `gen/android/megathrone-release.jks` + `signing.properties` (deliberate: a sideloaded app needs one stable signature so updates install over previous builds; rotate to GitHub Secrets before any Play Store plans). CI's `build-android` job produces `megathrone-<tag>-android-arm64.apk` and attaches it to releases.

## pnpm quirks

- pnpm 11 reads build-script allowances from `pnpm-workspace.yaml` (`allowBuilds: esbuild: true`). The `pnpm.onlyBuiltDependencies` field in package.json is deprecated and silently ignored.
- The Tauri CLI runs `pnpm install` before its commands — a broken `pnpm-workspace.yaml` breaks every `pnpm tauri ...` invocation with a confusing stack trace.

## Architecture

- `src-tauri/src/lib.rs` — app setup, AppState (`Mutex<rusqlite::Connection>` + auto-update `Notify`), command registry, plugins (shell, dialog).
- `src-tauri/src/db.rs` — SQLite schema/migrations (idempotent: `CREATE IF NOT EXISTS` + `add_column_if_missing`; exceptions — the v8 rework gate, which ran once to replace test-URLs/route-rules with per-category actions, the v9 gate, which rebuilt `test_sites` into typed routing rules: old URL rows kept their ids as `url`-typed rules, the FK'd result tables were rebuilt empty, and the YouTube/Discord categories gained a whole-domain `domain_suffix` rule each; and the v10 gate, which added `profiles.selection_mode` — rows with a checkmark became `manual`, everything else `fastest`; and the v11 gate, which delivered the default catalog's new whole-domain `domain_suffix` rules (`googlevideo.com` → Google Video, `ytimg.com`/`ggpht.com` → YouTube, `t.me` → Telegram, `twimg.com` → Social) into existing DBs by category name, `NOT EXISTS`-guarded). DB lives in the OS app data dir (`app.path().app_data_dir()`, e.g. `~/Library/Application Support/com.megathrone.app/megathrone.db`), created on startup.
- `src-tauri/src/parser.rs` — subscription/link parser: vless/vmess/ss/trojan/hysteria2/tuic/socks5 share links, whole-payload base64, native sing-box configs. Every endpoint is stored as a ready-to-use sing-box outbound JSON (`outbound_json` column) — "connect" later means feeding it into a generated config. Tolerates broken generators (`&` instead of `?`, empty/duplicate tags, names with spaces, junk uTLS fingerprints — `UTLS_FINGERPRINTS` whitelist). SSR links are intentionally skipped.
- `src-tauri/src/profiles.rs` — Tauri commands as thin wrappers over pure storage-layer functions (`list_profiles`, `import_profile`, ...). Keep that split: the storage fns are what tests exercise (`#[cfg(test)]` there). Profile sources: `source_url` (refresh = fetch), `source_path` (refresh = re-read file), pasted text (not refreshable). `last_fetched_at` + `auto_update_minutes` drive background updates. `update_profile_flow` applies fresh content as a **diff** matched by raw link (multiset for duplicates): surviving endpoints keep their row id and every test result (`available`/`latency_ms`/`last_tested_at`, deep-probe rows), removed links' rows are deleted (results cascade), new links inserted, display fields (`tag`/`order_index`) follow the fresh content; it first stops a running scan via `latency::cancel_and_wait` (bounded wait, scan exits between batches), and a *set* change (inserts/removals, a pure reorder is not one) triggers `rebuild_session_after_update` — a reconnect of the live session, with the restart toast for the manual button and silent (errors → `last_error`) for the scheduler. Every update phase also emits a global `PROFILE_UPDATE_EVENT` notice (started/success with the diff counts/error). Every mutation must call `after_mutation(app, Some(id), CONTENT|META|LATENCY|SELECTION)` — it emits the `profiles-changed` Tauri event and re-arms the scheduler. Endpoint cards carry a per-endpoint deep-probe score (`url_ok`/`url_total` counted from `endpoint_url_results` joined to *proxy*-action categories; 0/0 — not deep-probed in the last scan). Endpoint selection = `selected_endpoint_key` (raw link, survives updates) + `selection_mode` (`round_robin`|`fastest`|`most_available`|`manual`): the pure ranking fns (`pick_fastest`/`pick_most_available`/`pick_round_robin` over `load_candidates`, which skips broken outbounds and marks reachable endpoints whose deep-probe share is under the availability floor — Settings → General, `min_availability_percent` — as dead; `load_reachable_candidates` drops them instead) decide automatic picks — round robin rotates strictly among scan-reachable endpoints and never lands on an untested or known-dead one (a never-scanned profile still dials its first endpoint); `profile_select_endpoint` always flips the mode to `manual` (an explicit pick is a manual pick); `profile_item_index` resolves an endpoint's 0-based position in the canonical order `profile_items` pages (shared `CANONICAL_ORDER` const).
- `src-tauri/src/auto_select.rs` — the automatic-selection supervisor: one task per *connected* profile with an automatic `selection_mode`, running on two clocks read from the general settings each loop (edits apply without a reconnect): the *re-check* clock (`recheck_interval_minutes`, default 10) runs a `latency::run_scan` (scope per `pass_scope`: reachable-only re-check, full when the pass is sticky or nothing is reachable is known) and applies the strategy's verdict — fastest/most_available switch only on a clear win (hysteresis consts in the module; a dead/unknown current always switches), round robin only replaces a current that is not provably reachable; the *rotation* clock (`rotation_interval_minutes`, default 10, round robin only) rotates to the next reachable endpoint (scanning first when no reachable set is known). The scan calls `rescue` after every persisted batch: a reachable current waits for the pass verdict, but a dead/untested/dangling one moves to the strategy's reachable pick mid-scan (`rescue_pick`). A switch = persist the pick + `profiles-changed: selection` + `connection::switch_endpoint_if_running` (a live selector flip; `restart_if_running` only as its fallback). `update_profile_flow` pokes it via `content_updated` into a *sticky* pass: the diff kept every survivor's results, so the pass scans only never-tested rows (`UntestedOnly` — a full scan only when no reachable set survived) and the current endpoint is kept while it survived the update and stays alive. Lifecycle: armed by connect/mode-switch (`ensure`, generation-keyed so a re-arm kills the old task), stopped on disconnect/unexpected exit/manual mode. Two clock timestamps (`last_scan`/`last_switch`) carried across re-arms stop a switch-restart from re-scanning immediately (a pending update still runs right away). `apply_now` (+ `mark_pass_now`) is the mode-switch path: pick per strategy from current data, switch (live) if the endpoint changes, no immediate supervisor double-verdict. User-initiated reconfigurations (endpoint pick, mode switch, DPI change, profile switch) report through `connection::emit_restart_result` (`restart-result` event → the global `NotificationsToast` in `AppLayout`: successes auto-hide, errors stay copyable); background supervisor switches and rescues stay silent.
- `src-tauri/src/scheduler.rs` — single background task (tokio + `Notify`): wakes at the next due time computed from the DB (`next_wake_seconds`), or immediately when nudged; updates due profiles via `update_profile_flow` (a set change rebuilds the live session silently through `rebuild_session_after_update`); failed passes back off 5 min (no busy loop on a permanently-due profile). DB lock is never held across network/file IO.
- `src-tauri/src/latency.rs` — availability scans (URL test): a throwaway sing-box instance is spawned with every endpoint as an outbound (synthetic `mt-N` tags, direct as route default) and the clash API enabled on a random local port; per-endpoint latency = a real HTTP request through the proxy (`GET /proxies/{tag}/delay?url=…`, the Clash-GUI URL test), batched (`latency-progress` event per batch carries the batch's results — never per-endpoint events). Endpoints passing the base probe are additionally **deep-probed** against the test-marked probeable rules of *proxy*-action categories (`sites::flat_test_rules`) — every base-passing endpoint is deep-probed. Rows land in `endpoint_url_results`; endpoints that failed the base probe get their stale rows cleared. Before starting, configs are `sing-box check`-validated with bisection (`isolate_bad_outbounds`) — rows the current sing-box cannot load (legacy junk) are marked unavailable instead of failing the scan. Base results go to `available`/`latency_ms`/`last_tested_at`. A scan runs over a `ScanScope`: `All` (the manual button, sticky passes with no reachable set, profiles with nothing reachable known), `ReachableOnly` — the supervisor's regular passes re-check just the endpoints the last scan proved reachable (cheap when most of a large profile is dead) — or `UntestedOnly` — the post-update sticky pass: the diff kept survivors' results, so it scans only never-stamped rows (fresh links plus the untested tail of a scan the update cancelled). Scan writes tolerate endpoints deleted mid-scan by a concurrent update/delete (`apply_url_probes` skips dangling ids), and `cancel_and_wait` (what the update flow calls) stops a scan cooperatively between batches and blocks for its exit. After every persisted batch the scan calls `auto_select::rescue`: a connected automatic-mode profile whose current selection is not provably reachable moves to the strategy's reachable pick mid-scan instead of waiting out the rest of it. A process-wide scan registry (`SCANS`) backs `profile_latency_status` (adopt a running scan after remount) and `profile_cancel_latency` (flag checked between batches; `ScanGuard` removes the entry on any exit path). `SingBoxGuard` kills the sidecar and removes the temp config when the scan ends (kept on startup failure for debugging, path in the error).
- `src-tauri/src/connection.rs` — the long-lived proxy session: sing-box runs with **every parseable endpoint of the profile baked into the config behind a `selector` outbound** (tag `mt-proxy`, synthetic `mt-1…mt-N` endpoint tags, `default` = the selected endpoint, `interrupt_exist_connections` off). An endpoint change while connected is one Clash API PUT (`switch_endpoint_if_running`: new connections ride the new endpoint instantly, open ones drain on the old one — no restart, no port/TUN/system-proxy churn); it falls back to `restart_if_running` when the target was not baked (fresh content, DPI-only session) or the API call fails. Only changes that alter the config itself (content updates, routing, DPI, mode, profile switch) reconnect. The raw local proxy (Settings → General, on by default, `raw_proxy_port` default 7890) is a second mixed inbound (`mt-raw-in`) whose rule sits **above every route rule** (the private-range direct rule included) and rides `mt-proxy` — apps with a built-in proxy setting point at `127.0.0.1:<port>` and send everything through the selected endpoint, following its live switches; a busy configured port falls back to a random free one (`resolve_raw_port`, short retry window for a dying previous instance) and the actual port ships as `ConnectionSnapshot.raw_proxy_port` (copied from the Home status line); a DPI-only session bakes no port. An absent/dangling/broken selection — or, for automatic strategies, one the last scan marked dead — is auto-picked per the profile's strategy before the config is built (manual falls back to fastest), so a connect never blocks on the checkmark — only a profile with nothing dialable at all can fall back to a DPI-only session. The pre-spawn `sing-box check` rejects (one bad baked outbound fails the whole config) are handled by `isolate_and_repick`: it re-validates every outbound via `latency::isolate_unloadable_outbounds` (the scan's bisection), marks the unloadable rows unavailable and re-picks among the survivors; an explicit manual selection surfaces the error instead. Routing categories from `routing.rs` become sing-box route rules (one rule per category × matcher kind, in category order; `url` rules ride the `domain_suffix` bucket by their hostname) over three outbounds (`mt-proxy`, `mt-dpi`, `mt-direct`) with the configured fallback as `route.final` (domain rules get a `{"action":"sniff"}` rule so TUN/bare-IP connections resolve to hostnames). When routing needs the DPI tunnel *and* the DPI master toggle is on, the byedpi sidecar is spawned first (`-i 127.0.0.1 -p <settings port>` + the active strategy's arg line); readiness = a TCP connect to that port, distrusted when the port answers before ever refusing one (a stale tunnel from a crashed run holds it while our child dies with `bind: address already in use` — the probe waits out a short grace for our child's termination and fails the connect honestly instead of going ready on someone else's listener). With the master toggle off the tunnel never starts — dpi categories stop matching (traffic falls through to the fallback) and a dpi fallback degrades like any missing tunnel. A dpi *fallback* without a selected strategy (DPI on) is a hard connect error (silent misrouting would be worse); dpi *categories* without one are simply skipped. An unexpected ciadpi exit is reported as `last_error` via the dpi watcher (deliberate kills silenced by an `AtomicBool`) without tearing the session down. Crash recovery (`SessionMarker`, `dpi_pid` serde-defaulted) kills an orphaned ciadpi by `ps` comm too (the needle is the on-disk name `byedpi` — the comm is the executable path, upstream's `ciadpi` never appears in it). The traffic poller (`start_traffic_poller`, generation-keyed like the session) reads the clash `/connections` snapshots ~1 Hz: per-connection byte deltas fold into per-outbound totals emitted as `traffic-stats` (the Home charts), and every *new* connection id additionally counts as one request to its host (`metadata.host`, falling back to `destinationIP:port`) through its tunnel into the session-scoped per-URL table (`URL_STATS`, cleared on connect, frozen on disconnect) — a connection leaving the snapshot finalizes its outcome there (any response bytes → ok, closing mute → failed; open ones count as requests only). Served by `connection_url_stats` (the Stats page).
- `src-tauri/src/dpi.rs` — byedpi strategies (Settings → DPI, `DpiStrategiesSection`): CRUD + single "active" selection over `dpi_strategies`. The arg line is validated by `parse_strategy_args` to reject options the app owns (`-i/-p/-D/-w/-E` + long forms, including glued values like `-p1080`). Also owns the `dpi_port` app setting and the `dpi_enabled` master toggle (Settings → DPI): off — the tunnel never spawns and a connect is proxy-only. Ships 61 named preset strategies (`PRESET_STRATEGIES`, adapted from ByeByeDPI's `proxytest_strategies.list`, `{sni}` baked in as `google.com`, plus the brute-force "Despair" `DESPAIR_ARGS`) seeded by `seed_default_strategies` from app setup — only into an empty table, never over a user collection. Strategy score counters count only *dpi*-action category rules marked for testing of probeable types.
- `src-tauri/src/sites.rs` — URL categories (Settings → Routing): `test_site_categories` + `test_sites`, CRUD over both (`sites_add_rule`/`sites_update_rule`/`sites_set_rule_test`/`sites_delete_rule` + category commands), `test-sites-changed` event after every mutation (including action flips). Rule/category mutations that reach the generated config also apply to the live session via `routing::apply_routing_change_live`. Every category member is a **typed routing rule** (`rule_type`: `url` | `domain_suffix` | `domain` | `domain_keyword` | `domain_regex`, values validated per type by `validate_rule_value`) with a `test_enabled` flag — tests see only test-marked rules of probeable types (`flat_test_rules` derives the probe URL: URLs as-is, bare domains as `https://<value>/`; keyword/regex are routing-only). Each category carries an `action` (`dpi`|`proxy`|`direct`, switched in the Routing list via `sites_set_action`): dpi categories feed the strategy test and route into the DPI tunnel; proxy categories feed the endpoint deep probe and route through the proxy; direct categories bypass both. Default catalog (`DEFAULT_SITES`, from ByeByeDPI's `proxytest_*.sites`, seeded as `domain_suffix` rules) seeded by `seed_default_sites` from app setup, also only into an empty table. FK cascades keep `dpi_url_results`/`endpoint_url_results` consistent with edits.
- `src-tauri/src/dpi_test.rs` — the strategy test (Settings → DPI): per strategy, a throwaway ciadpi is spawned on a random port (readiness via `connection::probe_dpi_ready`) fronted by a throwaway sing-box (single socks outbound → ciadpi, clash API); every test-marked probeable rule of the dpi-action categories is fetched through the tunnel with the clash delay endpoint (`latency::url_test_chunk`), results upserted into `dpi_url_results` and announced per strategy via `dpi-test-progress` (+ final `dpi-test-finished`). A single-entry registry backs `dpi_test_status`/`dpi_cancel_test` (adopt/cancel after remount). Refuses to run while the proxy is in TUN mode (its routes would capture the probes). The strategy list is auto-sorted by last test results (live re-ordering while a test runs).
- `src-tauri/src/routing.rs` — routing = URL categories + fallback: `load_routing` returns every category with its action and typed rules (junk rule types skipped), plus the `route_fallback` setting; `dpi_used` = dpi fallback or any dpi category. There are no hand-written rules anymore (the old `route_rules` table was dropped in the v8 migration). Skips junk rows instead of ever failing the connect flow. While a session runs, routing mutations apply live: `routing_set_fallback` (on a real change) and the config-affecting `sites_*` commands route through `apply_routing_change_live` (restart + `restart-result` toast); no-op mutations never restart (category rename, test toggles, empty-category add/action, same-value re-sets).
- `src-tauri/src/settings.rs` — General settings (Settings → General): the supervisor cadences (`rotation_interval_minutes`, `recheck_interval_minutes`, both default 10 minutes, 1..=1440), the availability floor (`min_endpoint_availability_percent`, default 55, 0 = off), the raw local proxy (`raw_proxy_enabled` default on + `raw_proxy_port` default 7890; `settings_set_raw_proxy` reconnects the live session iff the baked inbound would change — toggle flip or port swap, DPI-only sessions and no-ops never restart) + the shared `validate_test_url` normalizer. Commands: `settings_get_general`/`settings_set_cadences` (the whole Automatic-strategies card: both cadences + the floor), storage fn `load_general` (all keys, junk falls back to defaults).
- Frontend: routes are `/` (Home), `/stats` (`Stats` — session statistics, opened by clicking the connected traffic dock on Home: sticky header with a Back button, a per-URL request summary on top — host + tunnel badge (Proxy/DPI/Direct in the chart palette) + ok/failed/total counts, fed by `useUrlStats`, an `UrlStatsProvider` context mounted in `AppLayout` next to `TrafficStatsProvider` — and the same `TrafficDock` charts at the bottom, full window width and flush to the window bottom like Home's dock), `/profiles…` (`src/pages/profiles/`), `/settings` and `/settings/categories/:id` (`CategoryPage` — the rule editor of one category: sticky header with back/rename/delete, per-rule cards of value + matcher-kind tabs + a Testing toggle, and an add-rule form; reached by clicking a category row in the Routing list). The endpoints page header carries the strategy tabs (`round_robin`/`fastest`/`most_available`/`manual`, `useProfileSelection`) with the selected endpoint as a compact one-line row below — the selected endpoint stays in the grid too (success-border highlight); clicking the compact row scrolls the grid to its card (`profile_item_index` + `VirtualWindowGrid`'s imperative `scrollToIndex`), and clicking any card is an explicit (manual) pick (a no-op on the already-selected one). Data hooks live in `src/hooks/data/` (createResource + invoke). Reusable UI in `src/components/{common,profiles,layout}/`. Settings tabs: DPI (`DpiSection` — the master toggle + port; `DpiStrategiesSection` below it, both revealed by `TransitionCollapse` only while DPI is on), Routing (`RoutingSection` — the URL-category list: per-category tri-state, row click opens the category page, an inline "+ Category" creator, plus the fallback; the fallback hides its DPI option — resetting a stale dpi fallback to proxy — and warns that DPI routes degrade to the fallback while DPI is off or no strategy is selected), General (`GeneralSection` — the automatic-strategy cadences: endpoint rotation and reachable re-check intervals, the min-availability floor under which an endpoint counts as dead, and the Local proxy card: enable toggle + fixed port for the raw endpoint-bound port). `/settings` reads `?tab=` for deep links (the category page's back button uses `?tab=routing`; General is the default tab).
- Frontend reactivity to backend changes: hooks subscribe to the `profiles-changed` event (payload `{ profileId, kind: "content" | "meta" }`). `kind === "content"` makes the endpoints page reset pagination and scroll to top (the list can shrink a lot on update). `connection_switch_profile` (Home profile dropdown while connected) re-points the live session at another profile, keeping the mode; its outcome — like every user-initiated reconfiguration — arrives as `restart-result` and is shown by the global `NotificationsToast` mounted in `AppLayout` (successes auto-hide, errors stay copyable). Every profile update — manual or scheduled — also narrates itself globally via `profile-update` events (`ProfileUpdateNotice`: started/success/error with the diff summary; started/success auto-hide, errors stay copyable) into the same toast stack. `AppLayout` also mounts the global `ScrollTopButton` (`src/components/common/`) — bottom-right, appears past ~300px of window scroll, instant jump (one virtual-window load).
- Import path aliases use `@/` (→ `src/`), configured in both `vite.config.ts` and `tsconfig.json`. Prefer `@/` over deep relative imports.

## SolidJS conventions (violated = runtime bugs)

- Hooks expose reactive state as **functions** (`loading()`, `error()`), never as getter properties on a plain returned object — destructuring such an object freezes the value (caused an infinite-spinner bug once).
- Named exports + `Component<Props>` arrow functions; no default exports. Control flow via `Show`/`Switch`/`Match`/`For`, not ternaries/`&&` in JSX. `Dynamic` for optional component slots. No `JSX.*` types — take `Component` props instead.
- Icons: Tabler set from `solid-icons/tb`, exported as `TbOutline*` / `TbFill*` (NOT the upstream `Tb*` names). Full list: `node_modules/solid-icons/tb/index.d.ts`.
- Tailwind v4: no `tailwind.config` — DaisyUI plugs in via `@plugin "daisyui"` in `src/index.css`. Don't build class strings dynamically; `classList` for conditionals.

## TypeScript setup

- Two projects: `tsconfig.json` (browser code under `src/`, DOM libs, no node types) and `tsconfig.node.json` (`vite.config.ts`, `types: ["node"]`). Keep `@types/node` out of the src config — `process` is intentionally unavailable there.
- `tsc` does not run during `vite build`; `pnpm typecheck` is the only gate.
